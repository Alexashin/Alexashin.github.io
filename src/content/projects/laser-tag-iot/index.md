## Бизнес-задача
Сделать аттракцион, где попадание водой засчитывается как игровое событие: счёт, время, табло для зрителей. Площадка может работать без интернета, оператор не техник.

## Решение
Жилеты с Zigbee-датчиками протечки, координатор с MQTT, сервер в локальной сети. Оператор ведёт матч с планшета, на ТВ выводится публичное табло, статистика сохраняется. Режимы: командный бой, свободный, базы.

## Что получил клиент
- Работающий продукт для площадки: матч запускается из одного экрана.
- Готовность к игре видна заранее (связь, мокрый датчик, батарея, офлайн).
- Спорные попадания разбираются по журналу событий с причиной решения.

## Какие вопросы закрыты
Работа без интернета, привязка нового датчика в один клик, защита от «залипшего» мокрого датчика, восстановление матча после перезапуска сервера, роли Admin / Operator / Viewer.

## Технические моменты
- Автомат состояний жилета (готов, пауза после попадания, ожидание высыхания): датчики сообщают только о переходе «сухо, мокро».
- Общий lock для MQTT и HTTP, снапшот матча в Redis, флаг сохранения результата и повтор при сбое записи, идемпотентные ответы 409.
- Hot-plug USB-донгла, утилита освобождения слотов координатора, тест дальности на 32 датчиках (29 рабочих).
- Устройства идентифицируются по IEEE-адресу, история миграции с Home Assistant сохранена.
