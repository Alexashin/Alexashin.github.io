## Бизнес-задача
Дать гостям из печатного меню бонус по промокоду. Каждый человек получает один код, ничего не раздаётся дважды, а отчётность остаётся в привычной Google Таблице.

## Решение
Telegram-бот: гость выбирает направление (парк, парк животных, глэмпинг), получает текст со скидкой и уникальный код. Администратор в боте смотрит статистику за последние дни и перезагружает коды из таблицы.

## Что получил клиент
- Подготовлено по 100 уникальных кодов на направление, раздача без участия сотрудников.
- Учёт «кто и когда получил код» ведётся автоматически в той же таблице, куда привыкли смотреть.
- Правило «один человек, один код» держится на стороне бота.

## Какие вопросы закрыты
Раздача кодов без ручной работы, учёт использования, быстрая статистика для администратора, возможность пополнять коды из таблицы без правок кода.

## Технические моменты
- Google Таблица как источник и отчёт, Redis как быстрый кэш очередей кодов и множества получивших.
- Запись в таблицу идёт в отдельном потоке, чтобы бот отвечал мгновенно. Фоновые мониторы Redis и таблицы.
- Развёртывание: docker-compose (Redis + бот).

## Что можно улучшить (честно)
Проверка «уже получал» и выдача кода сейчас не атомарны, при гонке теоретически возможны два кода одному человеку. Лечится одной атомарной операцией Redis. Тестов нет.
